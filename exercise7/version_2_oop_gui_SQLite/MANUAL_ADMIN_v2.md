# ⚙️ РУКОВОДСТВО АДМИНИСТРАТОРА ПРИЛОЖЕНИЯ «Система управления фермерскими рынками» (ВЕРСИЯ 2: GUI, ООП, данные в БД)

## 1. Системные требования
* **Операционная система:** Windows 10/11.
* **Стек технологий:** Python версии 3.8 или выше.
* **База данных:** Встроенный движок SQLite3 (дополнительная установка СУБД не требуется).
* **Интерфейс:** Пакет Tkinter (входит в стандартную сборку Python на Windows).

## 2. Полная структура каталогов проекта

## 3. Развертывание и первый запуск (Миграция)
Администратор обязан инициализировать базу данных перед тем, как пользователи начнут работу с графическим интерфейсом.

1. Поместите исходный текстовый файл `Export.csv` в общую папку данных по пути `rebase_EX_7/data/`.
2. Зайдите в папку второй версии `version_2_oop_gui_SQLite` и запустите файл развёртывания двойным кликом мыши:
   * 🛠️ **`setup_Ex7_v2.bat`**

**Логика работы автоматизации:** Батник сделает шаг назад (`..\`), обнаружит корень проекта `rebase_EX_7`, создаст там изолированное окружение `.venv` и запустит `migrations.py`. Скрипт миграции считает файл `data/Export.csv` и пакетами по 1000 строк (метод `executemany`) создаст готовую реляционную базу данных `markets.db` в папке `data/`.

## 4. Запуск клиентского приложения
Для старта программы и открытия графического интерфейса запустите двойным кликом батник внутри папки второй версии:
* 🛠️ **`run_Ex7_v2.bat`**

В файле `app.py` настроен защитный триггер. Если администратор забыл выполнить миграцию, программа выдаст в консоль понятное текстовое предупреждение о необходимости первоначального запуска `setup_Ex7_v2.bat` вместо аварийного падения оболочки.

## 5. Запуск юнит-тестов
Для проверки работоспособности логики базы данных, тригонометрических формул расчета миль и пагинации страниц без риска повредить реальные рабочие данные, в проект интегрированы автоматические тесты. Запустите батник:
* 🛠️ **`run_tests_Ex7_v2.bat`**

Тестирование происходит изолированно в оперативной памяти компьютера (`:memory:`). В случае успешной проверки всех узлов (пагинации, связи ООП-моделей и каскадного удаления отзывов) утилита выдаст в консоли финальный статус **`OK`**.

## 6. Безопасность и стабильная эксплуатация
* **Каскадное удаление данных:** В приложении на уровне СУБД активирован режим `PRAGMA foreign_keys = ON;` (внутри `db_manager.py`). При удалении рынка из таблицы `markets` все связанные с ним отзывы из таблицы `reviews` стираются базой данных автоматически.
* **Защита от SQL-инъекций:** Все поисковые и записывающие запросы в `db_manager.py` спроектированы исключительно с использованием параметров-заполнителей (знаков `?`), что полностью защищает базу данных от взлома через поля ввода фильтров.
* **Устойчивость к сбоям:** Все вызовы СУБД в графической оболочке `gui_views.py` защищены блоками `try-except`. При возникновении аппаратных ошибок приложение выведет понятное окно с предупреждением вместо экстренного вылета процесса.
* **Резервное копирование (Backup):** Так как SQLite хранит всю базу в одном файле `markets.db`, для создания бэкапа достаточно скопировать этот файл из папки `data/` в любое безопасное место.
